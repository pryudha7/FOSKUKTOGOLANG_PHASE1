# Schema additions beyond SoT §9, each agreed one by one

The schema follows SoT §9 exactly (CLAUDE.md), but §9 leaves gaps the code cannot work around, so a few tables and columns were added, each only after asking the user: `operator` (ENT-005 names the fields but §9 has no table; full field list TBD-018), `operator_session` (server-side sessions, so idle timeout and logout are enforced on the server), `access_groups` (referenced by `role_access_mappings` in §9.3 but never defined there; modelled on `work_groups`), and on `work` the columns `customer_type` (the BMV CUSTOMER_TYPE description) and the `slik_*` SLIK Request Data codes (TBD-039b asks where they live; stored on `work` like `customer_type`). We chose small additions next to the existing §9 tables over a parallel schema of our own, so that when the SoT owner fills these gaps the change is a migration on a known column, not a redesign. Anything else §9 lacks still means stop and ask, not add.
